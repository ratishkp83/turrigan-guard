# Self-hosted Enterprise deployment (sovereign / off-store)

For clients whose IT will not allow a Chrome Web Store install, the Enterprise edition can be
**force-installed from a signed `.crx` you host yourself**. Chrome and Edge permit this only for
enterprise-managed, force-installed extensions (a normal user cannot install an off-store `.crx`).
Personal is store-only; this path is Enterprise-only.

## Stable extension IDs (do not change)

The manifest `key` field pins a constant id per edition across every update. Managed policy and the
force-install list reference these ids:

| Edition | Extension ID |
|---|---|
| Personal | `ehklamohfapoghhffcoemikbkcjnmipe` |
| Enterprise | `lgmabljmaealpiaddahlmlohicohljdp` |

## 1. Build and sign the `.crx`

The signing key is `signing/enterprise.pem` (generated by `signing/gen_keys.sh`, kept in your secure
store, never in git). Assemble the folder, then pack + sign with Chrome:

```
node build.js
"C:\Program Files\Google\Chrome\Application\chrome.exe" ^
  --pack-extension="%CD%\enterprise" ^
  --pack-extension-key="%CD%\signing\enterprise.pem"
```

This writes `enterprise.crx` next to the folder, signed with your key, so its id is the stable
enterprise id above. (On macOS/Linux use the platform Chrome path with the same two flags.)

## 2. Host the `.crx` and the update manifest

Publish two files on your HTTPS server (for example `https://turrigan.com/guard/`):

- `enterprise-<version>.crx` (the signed package)
- `updates.xml` (the update manifest in `docs/self-host/updates.xml`), with its `codebase` pointing at
  the `.crx` URL and `version` matching the package. Bump both on every release; browsers poll
  `updates.xml` and auto-update.

## 3. Force-install by policy

Point the force-install policy at the update manifest (not the store). The value is
`<extension-id>;<update_url>`:

- **Windows GPO / registry** (Chrome): under
  `HKLM\Software\Policies\Google\Chrome\ExtensionInstallForcelist`, add
  `lgmabljmaealpiaddahlmlohicohljdp;https://turrigan.com/guard/updates.xml`
- **Edge**: same under `HKLM\Software\Policies\Microsoft\Edge\ExtensionInstallForcelist`.
- **Google Admin console / Intune**: use the same id + update-URL value in the managed-browser
  extension policy.

Push the tenant configuration (`apiBaseUrl`, `apiKey`, optional `userId`/`orgId`) via the managed
policy at the same time, keyed by the extension id. See the WI-P7 IT deployment kit and
`enterprise/schema/managed_schema.json`.

## 4. Verify

On a managed browser, `chrome://extensions` (or `edge://extensions`) shows Turrigan Guard for
Enterprise **installed by your organisation** and not removable, its id matching the table above, and
the popup Subscription reading **active** once the managed `apiBaseUrl` + `apiKey` are applied.
